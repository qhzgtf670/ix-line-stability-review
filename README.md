# IX专线稳定性：从通报风险到晚高峰表现，MKCloud四条IX线路的接入条件、价格与全部套餐一次讲清

搜“IX专线稳定性”的人，多半已经被两条消息折磨过：要么是IEPL/IPLC入口被扫段、整个段被打死；要么是隔三差五收到服务商“配合整改、临时停机”的通知。linux.do上讨论线路选择的帖子里，相当一部分老玩家的结论很直白——目前主玩IX专线，原因就是IEPL和IPLC被通报得太频繁，而IX没有公网入口，扫段扫不到。

这个判断有它的道理，但也有边界。这篇文章把IX专线为什么“稳”、稳在哪里、哪些风险它照样扛不住讲清楚，再以目前社区讨论度最高的MKCloud（mkcloud）为例，把它的四条IX线路、接入条件、全部套餐价格和真实的稳定性记录摊开来看。看完你应该能判断：IX到底适不适合你的业务，以及选哪家、选哪档。

## IX专线的“稳”，本质是入口藏起来了

先说机制。IX（Internet Exchange，互联网交换中心）专线的入口不是公网IP，而是交换中心的内网地址，只和阿里云、腾讯云、华为云这类大厂的云网络交换路由。你的流量从云主机内网连上IX入口，走专线出境，全程不暴露公网入口。

这带来三个直接后果：

- **公网扫段基本失效。** 入口没有公网路由，自动化扫描工具找不到目标，像“整个IP段被通报清退”这类连环雷，在IX架构下很难被触发。
- **公网DDoS打不到入口。** 攻击者摸不到入口，攻击成本被抬高到需要依赖云厂强实名资源，普通规模的恶意流量基本无从下手。
- **通报风险没有消失，而是转移了。** 这是很多人忽略的一点：IX不暴露公网，但你的前置云机是实名租的，一旦业务违规，追责路径非常清晰，责任直接落在用户头上。

还有两个务实的提醒。第一，IX的时延通常略高于极致优化的传统直连专线，因为流量要先经过一段前置网络才能进专线内网，这是架构决定的。第二，接入门槛不在链路本身，而在前置资源的选择——这部分后面单独讲。

另外要打破一个迷思：IPLC、IEPL、IX只是三种不同的技术形态，服务商官方资料里也明确写了“不能直接当作稳定性从低到高的排序”。IX的优势集中在入口隐蔽性和通报风险控制上，而不是玄学意义上的“更高级”。

## 真正决定你体验的，往往是前置那台云机

IX链路本身稳不稳，商家说了算；但你的整体体验稳不稳，前置云机占一半。这几点来自真实使用案例和官方知识库，买之前对照一遍：

1. **轻量实例的带宽不可信。** 目前性价比高的前置多集中在阿里云、腾讯云的轻量服务器，标称200M，但已有大量实例被实际限速到20M甚至1M的案例。峰值标称和实际吞吐是两回事。
2. **火山云延迟好但流量贵。** 火山引擎按量计费的流量成本约0.8元/GB，长期跑量不划算，适合短时高质量需求。
3. **入口方向可能波动。** 阿里云至深圳IX方向当前暂时不通就是活例子。如果你的业务依赖单一云厂前置，最好留一个备用接入方案。
4. **双向计量，超量即停。** MKCloud的计量型套餐按上行、下行双向统计流量，达到额度后停机。跑上传业务的要按双向峰值重新估流量，别只算下行。

## 开通之后，这样检查才算数

官方知识库给的使用流程值得照做：开通信息里核对入口、端口、系统、账号，先测入口连接，再在VPS里跑一遍有代表性的业务任务，确认实际出口和目标服务的响应。ping和mtr可以辅助观察，但端内延迟1~2ms指的是专线内部段，不等于你本地到目标的全程RTT。

## 常见问题

**IX一定比IPLC/IEPL稳定吗？**
不是绝对结论。IX的优势是无公网入口带来的抗扫段、抗通报能力；IPLC/IEPL在极致延迟上仍占优。如果你的痛点是入口被封、扫段和通报，IX更稳；如果是追求极限低延迟的直连体验，传统专线反而合适。

**1Gbps峰值能一直跑满吗？**
不能。共享带宽的峰值不保证持续速率，且流量双向计量、超量停机。需要持续速率就选带宽计费的独享类型，或者直接按月流量上限倒推选档。

**需要自己的ASN或BGP吗？**
零售用户不需要。交换中心成员接入是另一类服务，MKCloud的IX产品就是从云厂内网连入口，不涉及自建AS。

**能用来做公开服务吗？**
不能。所有IX和专线产品的出口都不接收入站，公开网站、支付回调、邮件接收、游戏服务端都不在服务范围内。违规用途（尤其机场、回国类）会直接清退且不退款。

**实名和退款政策是什么？**
全部产品需中国身份实名；仅质量问题支持退款，需在工单附具体测试数据，由商家审核判断；开通后不支持更换地域。

IX架构把入口藏起来的同时，也把一部分责任交到了你自己手上——前置选对、流量算准、合规使用，这条线路的稳定性才能真正兑现。
